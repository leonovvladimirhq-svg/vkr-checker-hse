# ВКР-чекер — правила для ИИ-ассистента

Веб-сервис НИУ ВШЭ (Школа коммуникаций) для автоматической проверки ВКР и курсовых по чек-листам
образовательных программ. Студент загружает `.docx`/`.pdf` и ссылку на базу данных (Яндекс.Диск),
сервис разбирает работу, обращается к языковой модели и выдаёт чек-лист со статусом. Две программы:
**ОП ИК** «Интегрированные коммуникации» (магистратура: проект и диссертация, плюс модуль курсовых)
и **ОП РиСО** «Реклама и связи с общественностью» (бакалаврская ВКР, пилот осени 2026).

Прод: https://вкр-чекер.рф (Yandex Cloud, Docker, модель Qwen 3.6 35B через Yandex AI Studio).

## Стек

Next.js 14 (App Router) + React 18 + TypeScript + Tailwind · SQLite через `better-sqlite3` (`data/vkr.db`, WAL) ·
`openai` SDK против OpenAI-совместимого API (`OPENAI_BASE_URL`) · `mammoth` (docx), `pdf-parse` (pdf, внутри —
pdf.js), `jszip`, `xlsx`, `docx` (генерация Word) · `nodemailer` (дайджест, не настроен) · Docker Compose + nginx + certbot.

## Команды

```bash
npm ci               # зависимости (точно по package-lock.json)
npm run dev          # http://localhost:3000
npm run build        # production-сборка — главная проверка перед коммитом (типы + сборка)
npm start            # запуск сборки
npx tsc --noEmit     # только проверка типов
```

Линтера и автотестов в проекте нет. Изменения проверяются так:
- `npm run build`;
- прогон на реальных работах;
- для API преподавателя — сценарии «кто что видит»: без входа 401, чужая работа 404.

## Жёсткие правила

1. **Репозиторий публичный.** Не коммитить пароли, ключи, `.env`, базу, файлы работ, ФИО студентов, а также
   документы с доступами. Значения секретов не писать даже в документацию: только имена переменных и место хранения.
2. **Объём работы считает код, а не модель** (`parser.ts` → `computeBodyVolume`, `volume.ts`). Числа объёма в
   промпт не передавать или явно запрещать модели их оценивать. Причина — баг с ошибкой ×10 от 11.06.2026.
3. **Программы описаны в `src/lib/programmes.ts`.** Не хардкодить списки типов работ и методов в UI или API.
   Промпты ОП ИК (`analyzer.ts`) и ОП РиСО (`riso-prompt.ts`) не смешивать.
4. **Каждый API преподавателя** начинается с `requireTeacher(req)` или `requireIkShared(req)` и фильтрует данные по
   `scopeOf(teacher)`. Чужая или несуществующая запись отдаётся через `notFound()` (404, не 403). `file_path` наружу
   не отдавать, только `has_file`. Middleware Next.js не использовать: в Edge Runtime нет `node:crypto` и базы.
5. **Шаблон отзыва ОП РиСО** (`riso-review-doc.ts`) собирается без модели: только перенос данных и арифметика.
6. **Исключение таблиц из объёма** (`excludeTablesFromVolume`) включено только в `/api/check`. Модуль курсовых
   менять только по решению заказчика.
7. **Миграции SQLite ленивые** (`initDb()` в `db.ts`, `ensureSchema()` в `db-course.ts`). Новая колонка добавляется
   через `ALTER TABLE ADD COLUMN` и в `CREATE TABLE`. Изменение `CHECK` требует пересоздать таблицу в транзакции
   по явному списку колонок; проверять это на копии боевой базы.
8. **Копию базы делать через SQLite backup API**, а не через `cp vkr.db`: база в режиме WAL, и свежие данные лежат в `-wal`.
9. **Телеметрия** (`telemetry.ts`) работает по принципу «отправил и забыл», с таймаутом. Персональные данные не передаются:
   ФИО только хешем, имя файла и тему не передавать.
10. **Параметры запроса к модели** выбирает `getModelParams()`: temperature, `max_tokens` или `max_completion_tokens`,
    JSON-mode. Модель меняется переменной `OPENAI_MODEL`, код при этом не правится. На проде модель задаётся URI
    `gpt://…`. Для Qwen во всех трёх вызовах модели (`analyzer.ts`, `course-analyzer.ts`, `course-review-prompt.ts`)
    ставится `reasoning_effort='none'`: без него модель тратит бюджет на рассуждения и возвращает пустой `content`.
11. **pdf.js для таблиц** — `require('pdf-parse/lib/pdf.js/v2.0.550/build/pdf.js')` литералом. Сборщику нужен
    статический путь. Версию v1.10.100 не брать: она роняет процесс. При любой ошибке нужен откат на `pdf-parse`.
12. Статус чекера — **подсказка**, а не оценка. Тексты интерфейса и отзывов не должны выдавать его за решение руководителя.

## Соглашения

- Язык интерфейса, комментариев, документации и сообщений коммитов — **русский**.
- Комментарий объясняет **почему**, а не что делает код. Если решение принято после бага, кратко назовите баг.
  Пример — `pdf-tables.ts`.
- Стиль коммитов: `feat(riso): …`, `fix(course): …`, `docs: …`, `chore: …`. Коммиты небольшие. В теле — что
  изменилось и почему.
- Код пишется в стиле соседнего: та же плотность комментариев, те же имена, та же идиоматика. Новых зависимостей
  без необходимости не добавлять.
- При изменении поведения обновить нужный раздел [ARCHITECTURE.md](docs/ARCHITECTURE.md) и добавить запись в
  [CHANGELOG.md](docs/CHANGELOG.md). Если принято решение с причиной — строку в [DECISIONS.md](docs/DECISIONS.md).
- После деплоя у пользователей с открытой вкладкой остаётся старый JS. Если человек «не видит изменений»,
  первым делом попросите обновить страницу.
