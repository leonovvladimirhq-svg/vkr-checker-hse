# VKR Checker

Веб-сервис автоматической проверки магистерских ВКР и курсовых работ для образовательной программы **«Интегрированные коммуникации»** Школы коммуникаций НИУ ВШЭ.

Студент загружает документ (`.docx` / `.pdf`), указывает ссылку на базу данных (Яндекс.Диск) — сервис анализирует работу через **Qwen 3.6 35B (Yandex AI Studio)** по чек-листу методических материалов программы и выдаёт подробный отчёт.

**Продакшен:** [вкр-чекер.рф](https://xn----ctbkawc3be3d.xn--p1ai) — развёрнут в **Yandex Cloud** (зона `ru-central1`).

**Полная техническая документация** — в [CLAUDE.md](./CLAUDE.md) (архитектурные решения, схема БД, история изменений). Этот README — точка входа для нового разработчика.

## Что умеет сервис

В сервисе **два независимых контура**, объединённых одной авторизацией и общей панелью преподавателя:

### 1. Модуль ВКР (`/`, `/teacher`, `/report`)
Проверка магистерских диссертаций (ИКР) и магистерских проектов (КП) по чек-листу. Выдаёт **три статуса**:
- **Зачёт** (`pass`) — все автоматические пункты пройдены, ручных нет;
- **Незачёт** (`fail`) — хотя бы один автоматический пункт провален;
- **Ожидает проверки** (`pending`) — есть пункты, которые нельзя проверить программно (длительность аудио, качество звука и т. п.) — финальное решение за преподавателем.

Преподаватель видит сводную таблицу всех студентов с попытками, статусами, может скачать загруженные работы, проставить итоговый зачёт/незачёт, опубликовать итоговый отчёт (со снапшотом результатов).

### 2. Модуль курсовых работ (`/course`)
Принципиально другой подход — **не pass/fail, а рекомендации**. ИИ-консультант анализирует работу, сверяет с методичками ОП ИК (2024–2025) и Программой практики 2025, выдаёт:
- общую оценку готовности (5 уровней — от «критические замечания» до «близок к зачёту»);
- сильные стороны работы;
- что стоит доработать;
- поразделный разбор структуры;
- **анализ базы данных** с Яндекс.Диска (доступность, состав файлов по типам, соответствие методам исследования);
- приоритетные рекомендации.

При отправке преподавателю генерируется Word-отзыв по шаблонам Приложения 20.1 / 20.2 Программы практики (с автозаполнением полей через GPT, красной пометкой о ручной проверке там, где авто-проверка невозможна, и обязательной декларацией использования ИИ в конце).

## Быстрый старт (локальная разработка)

**Требования:** Node.js 20+, npm 10+, Git.

```bash
# 1. Клонировать репозиторий
git clone https://github.com/leonovvladimirhq-svg/vkr-checker-hse.git
cd vkr-checker-hse
git checkout vkr-version-1

# 2. Установить зависимости
npm install

# 3. Создать файл .env в корне проекта.
# Прод использует Qwen через Yandex AI Studio (OpenAI-совместимый эндпоинт):
cat > .env <<EOF
OPENAI_BASE_URL=https://llm.api.cloud.yandex.net/v1
OPENAI_MODEL=gpt://<folder-id>/qwen3.6-35b-a3b/latest
OPENAI_API_KEY=<API-ключ сервисного аккаунта Yandex Cloud>
EOF

# 4. Запустить в режиме разработки
npm run dev
# Сервис доступен на http://localhost:3000
```

Папка `data/` и файл `data/vkr.db` создаются автоматически при первом запуске.

### Доступные npm-скрипты

| Команда | Что делает |
|---------|-----------|
| `npm run dev` | Запуск dev-сервера на `localhost:3000` с hot-reload |
| `npm run build` | Production-сборка (`.next/`) |
| `npm start` | Запуск production-сборки |
| `npm run lint` | Проверка ESLint |

### Переменные окружения (`.env`)

| Переменная | Обязательная | Описание |
|------------|--------------|----------|
| `OPENAI_API_KEY` | **Да** | API-ключ сервисного аккаунта Yandex Cloud (для Yandex AI Studio) |
| `OPENAI_BASE_URL` | **Да** (прод) | OpenAI-совместимый эндпоинт Yandex AI Studio: `https://llm.api.cloud.yandex.net/v1` |
| `OPENAI_MODEL` | **Да** (прод) | URI модели, напр. `gpt://<folder-id>/qwen3.6-35b-a3b/latest`. Параметры запроса (temperature / max_tokens vs max_completion_tokens / reasoning_effort) подбираются автоматически |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` | Нет | Для email-дайджеста преподавателю (опционально) |
| `DIGEST_RECIPIENT` | Нет | Email получателя дайджеста |

## Ключевые модули

### Промпт-инжиниринг
- **ВКР:** `src/lib/analyzer.ts` — системный промпт + чек-лист передаются в GPT, ответ парсится как JSON. Поддерживает множество моделей с автоматическим выбором параметров.
- **Курсовые:** `src/lib/course-analyzer.ts` — роль «ИИ-консультант по курсовым работам». `EXPECTED_SECTIONS` содержат `synonyms` + `keywords` для семантического сопоставления заголовков (студентский «бриф заказчика» матчится с каноническим «ТЗ»).

### Подсчёт объёма работы
`src/lib/parser.ts` → `computeBodyVolume(text)` ищет границы тела работы:
- начало — заголовок «Введение» (или после титульника по эвристике);
- конец — «Список литературы / источников» или «Приложение».

Возвращает `bodyCharCountWithSpaces` (главная метрика — порог 90 000 для рус), `bodyCharCountNoSpaces`, `bodyWordCount`, `appendixWordCount` и флаги `volumeBreakdown` (что удалось распознать).

### Проверка базы данных (Яндекс.Диск)
`src/lib/yandex-disk.ts` — рекурсивный обход публичной папки до 5 уровней с пагинацией, таймаутами и лимитом 300 файлов. `src/lib/db-analyzer.ts` — скачивает таблицы и документы (до 10 МБ), парсит структуру (имена листов, колонки, превью), формирует текстовое описание для GPT.

Используется и в ВКР, и в курсовом контурах без модификаций.

### Word-генератор отзыва
`src/lib/course-review-doc.ts` — рендер `.docx` через библиотеку `docx`. Структура соответствует шаблонам Приложения 20.1 (ИКР) и 20.2 (КП). Особенности:
- Жирная красная пометка (`color: C00000`, bold, 11pt) **«Рекомендуется ручная проверка»** — там, где авто-проверка невозможна (БД при null-счётчиках, корректность цитирования → Антиплагиат, ИИ-критерии при `yesNo === '—'`).
- **AI-дисклеймер** курсивом 10pt после подписи руководителя — обязательная декларация использования ИИ-помощника (этическое требование, симметричное правилам декларирования ИИ для студентов).

## Деплой (Yandex Cloud)

### Инфраструктура
- **Облако:** Yandex Cloud, зона `ru-central1-a`, каталог `project3-vkrchecker`.
- **ВМ:** Ubuntu 22.04, 2 vCPU / 4 ГБ RAM + 2 ГБ swap, статический публичный IP.
- **Запуск:** Docker (`docker compose`) — контейнер `vkr-checker` на порту 3000, `restart: unless-stopped` (автозапуск после ребута ВМ).
- **Nginx** (на хосте): reverse proxy на `127.0.0.1:3000`, SSL **Let's Encrypt/Certbot** (авто-продление). Параметры: `client_max_body_size 50m` (загрузка файлов), увеличенный `proxy_read_timeout` для долгих запросов к модели (особенно `location /api/course/`).
- **Домен:** `вкр-чекер.рф` (Punycode `xn----ctbkawc3be3d.xn--p1ai`).
- **Путь проекта на ВМ:** `/opt/vkr-checker/`. Данные (SQLite БД + загрузки) — в томе `./data:/app/data`.

### Модель (Yandex AI Studio)
Сервис обращается к **Qwen 3.6 35B** через OpenAI-совместимый эндпоинт Yandex AI Studio.
Настраивается в `.env` (реальные значения задаются при деплое, в репозиторий не коммитятся):
```
OPENAI_BASE_URL=https://llm.api.cloud.yandex.net/v1
OPENAI_MODEL=gpt://<folder-id>/qwen3.6-35b-a3b/latest
OPENAI_API_KEY=<API-ключ сервисного аккаунта Yandex Cloud>
```

### Обновление / деплой
```bash
ssh yc-user@<vm-ip>
cd /opt/vkr-checker
# обновить код (git pull или scp), затем пересобрать и поднять контейнер:

### Откат

```

## Сопровождение

### Логи
```bash
cd /opt/vkr-checker
sudo docker compose logs -f          # живой лог приложения
sudo docker compose logs --tail 200  # последние 200 строк
sudo tail -f /var/log/nginx/access.log
```

### Перезапуск
```bash
sudo docker compose restart   # перезапуск контейнера
```

### Если контейнер упал по OOM
- статус: `sudo docker compose ps` и `sudo docker stats --no-stream`;
- свободная память: `free -h`;
- swap включён? `swapon --show` (должен показать `/swapfile` 2G);
- лимит heap Node.js задаётся через `NODE_OPTIONS=--max-old-space-size` в `Dockerfile`/окружении.

### Обновление модели
Достаточно изменить `OPENAI_MODEL` в `.env` и пересоздать контейнер (`sudo docker compose up -d`). Параметры запроса (`temperature`, `max_tokens` vs `max_completion_tokens`, JSON-mode, `reasoning_effort`) подбираются автоматически в `getModelParams()` (см. `src/lib/analyzer.ts` и `src/lib/course-analyzer.ts`).

### Добавление новых методических материалов
Положи файл `.md` в `src/lib/methodology/` и подключи в `index.ts` через функцию `getMethodologyForCourse(type)` — содержимое автоматически попадёт в системный промпт GPT.

### Где менять что
| Хочу изменить | Где |
|----------------|-----|
| Чек-лист ВКР, пункты по методам | `src/lib/checklist.ts` |
| Промпт для ВКР | `src/lib/analyzer.ts` (функция `buildSystemPrompt`) |
| Промпт для курсовых | `src/lib/course-analyzer.ts` (функция `buildSystemPrompt`) |
| Ожидаемые разделы курсовой + синонимы | `EXPECTED_SECTIONS` в `src/lib/course-analyzer.ts` |
| Шаблон Word-отзыва на курсовую | `src/lib/course-review-doc.ts` |
| Промпт для заполнения Word-отзыва | `src/lib/course-review-prompt.ts` |
| Учётные данные | `src/app/page.tsx`, `src/app/teacher/page.tsx`, `src/app/course/page.tsx` (клиентская авторизация) |
| Пароль публикации отчёта | константа `REPORT_PASSWORD` в `src/app/api/report/route.ts` |

### Что НЕ покрыто автоматически (требует ручной проверки преподавателем)
- Длительность аудиозаписей и качество звука.
- Корректность цитирования и оригинальность (требует системы «Антиплагиат»).
- Содержание презентации (только сам факт ссылки проверяется).
- Любые разделы работы, вставленные изображениями (без распознаваемого текста).

Эти места явно помечены в UI (для студента) и **жирной красной пометкой** в Word-отзыве (для преподавателя).
